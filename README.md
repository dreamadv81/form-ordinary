# form-ordinary — обычные формы 1С:Предприятия 8.x в Claude Code

Навык для [Claude Code](https://claude.com/claude-code), который работает с **обычными (неуправляемыми) формами** 1С:Предприятия 8.x —
файлами `form.frm` и контейнерами `Form.bin` из выгрузки конфигурации. Навык читает форму, вносит в неё изменения, создаёт новые формы
и показывает, как форма будет выглядеть в режиме 1С:Предприятие. Он работает только с файлами: подключаться к информационной базе ему
не нужно.

## Возможности

- **Перевод в JSON и обратно.** Команда `decode` переводит `form.frm` в JSON, `encode` собирает из JSON файл, совпадающий с исходным
  байт в байт. Карта формата (`FORMAT.md`, `schema/`) описывает каждую позицию файла: имя поля, тип значения, назначение и
  соответствующее свойство в палитре свойств конфигуратора.
- **Проверка.** `validate` проверяет форму на трёх уровнях и повторным разбором собранного файла — ещё до загрузки в конфигурацию.
  Она же замечает табличное поле, тип которого не совпадает с типом его данных: такую форму платформа загружает без ошибки, но
  показывает таблицу без колонок (с выгрузкой конфигурации, `--config`, сверяется и тип таблицы на табличной части).
- **Изменение формы.** `edit --ops` вносит изменения списком операций: кнопки, элементы, колонки, страницы, обработчики событий,
  реквизиты, шрифты, привязки, любое свойство по имени из карты формата. Счётчики, индексы и взаимные ссылки операции поддерживают
  сами. Если результат операции ничем не подтверждён, она не выполняется и объясняет почему.
- **Новая форма.** `new` создаёт пустую форму — такую же, какую создаёт конструктор форм конфигуратора. `generate` собирает форму
  по описанию из готовых блоков: пары «надпись + поле», таблицы, закладки, панели, переключатели и другие. `describe` решает обратную
  задачу — строит описание по готовой форме. Для внешней обработки и внешнего отчёта навык читает корневой XML выгрузки (`--root-xml`):
  основной реквизит формы получает тип объекта, а поля и таблицы привязываются к его реквизитам и табличным частям так же, как это
  делает конструктор конфигуратора.
- **Расположение элементов и отрисовка.** `layout` рассчитывает, где окажутся элементы при любом размере окна. `render` рисует форму
  в SVG или PNG: элементы, рамки, закладки, командные панели, картинки и рамку окна. Форму можно показать в нескольких размерах окна
  рядом или сравнить вид «до» и «после» изменения.
- **Проверка оформления.** `lint` проверяет отступы (в том числе отступ от рамки страницы панели — 6 px, как у конфигуратора),
  шаг между элементами, размеры, наложения элементов и привязки. `anchors-check` и `repair-anchors` находят и исправляют формы,
  которые не растягиваются вместе с окном. Направляющие формы навык ставит так же, как конфигуратор, а элемент ниже нижней
  направляющей (из-за него в режиме 1С:Предприятие раскладка выходит за край окна) находит и исправляет операцией `normalize_guides`.
- **Досье формы для модели.** `brief` собирает описание формы: что видит пользователь при открытии, что меняется от его действий,
  как выглядит форма и что в ней можно менять. Модуль формы сначала разбирает модель по инструкции навыка, а навык проверяет её разбор.
- **`Form.bin` без конфигуратора.** `unpack` раскладывает контейнер `Form.bin` на `form.frm`, `form.bsl` и `info.txt`, `pack` собирает
  его обратно.
- **Обработка, собранная `ibcmd`.** `epf-copyinfo` дописывает в элемент `copyinfo` внешней обработки (`.epf`, `.erf`)
  ссылки её обычных форм: без них у такой обработки не компилируется модуль обычной формы. Сборка Конфигуратором в команде не нуждается.

Полный список команд и операций — в `form-ordinary/SKILL.md`, подробная документация по темам — в `form-ordinary/docs/` (указатель —
таблица «Тема → файл» в `SKILL.md`).

## Требования

- **Python 3.12 или новее.** Достаточно стандартной библиотеки, сторонние пакеты не нужны.
- **Для вывода в PNG** — любой из конвертеров SVG: `rsvg-convert` (`brew install librsvg` или `apt install librsvg2-bin`), ImageMagick,
  `inkscape`, в macOS также `qlmanage`. Без конвертера форма сохраняется в SVG.

## Установка

Скопируйте каталог `form-ordinary` в каталог навыков Claude Code: в `~/.claude/skills/` — чтобы навык был доступен во всех проектах,
или в `<проект>/.claude/skills/` — только в одном проекте. Claude Code подключает навык сам: встретив в работе обычную форму
(`form.frm`, `Form.bin`), модель прочитает `SKILL.md` и воспользуется командами навыка. Команды можно запускать и вручную, без Claude Code.

### macOS и Linux

```bash
cp -R form-ordinary ~/.claude/skills/
python3 ~/.claude/skills/form-ordinary/frm_json.py --help

# конвертер для PNG
brew install librsvg            # macOS
sudo apt install librsvg2-bin   # Debian, Ubuntu
```

### Windows

1. Установите Python 3.12 или новее (`winget install Python.Python.3.12` или установщик с python.org; при установке отметьте
   «Add python.exe to PATH»).
2. Скопируйте навык в каталог навыков пользователя (PowerShell):

   ```powershell
   New-Item -ItemType Directory -Force "$env:USERPROFILE\.claude\skills" | Out-Null
   Copy-Item -Recurse form-ordinary "$env:USERPROFILE\.claude\skills\"
   ```

3. Запускайте команды через `py` (или `python`); в путях — обратная косая черта:

   ```powershell
   py -3.12 "$env:USERPROFILE\.claude\skills\form-ordinary\frm_json.py" --help
   py -3.12 "$env:USERPROFILE\.claude\skills\form-ordinary\frm_json.py" decode "C:\Выгрузка\DataProcessors\Обработка\Forms\Форма\Ext\form.frm" -o form.json
   ```

4. Для вывода в PNG установите конвертер SVG: Inkscape (`winget install Inkscape.Inkscape`) или ImageMagick
   (`winget install ImageMagick.ImageMagick`). Без него форма сохраняется в SVG, который открывается в любом браузере.

Ширину подписей навык рассчитывает по шрифтам Microsoft Sans Serif и Tahoma. В Windows и macOS они установлены в системе, в Linux
их нужно установить отдельно — иначе ширина подписей оценивается приблизительно.

Навык разрабатывался и проверялся в основном в macOS. В Windows он рассчитан на ту же работу; вывод в консоль идёт в кодировке UTF-8.

## Быстрый старт

Примеры даны для macOS и Linux. В Windows команды те же, только вместо `python3 $F` пишут `py -3.12 <путь к навыку>\frm_json.py`;
в PowerShell путь удобно сохранить в переменную: `$F = "$env:USERPROFILE\.claude\skills\form-ordinary\frm_json.py"`, затем `py -3.12 $F …`.

```bash
F=form-ordinary/frm_json.py

# перевести форму в JSON и собрать обратно
python3 $F decode Ext/form.frm -o form.json
python3 $F encode form.json -o out.frm

# проверить форму
python3 $F validate Ext/form.frm

# изменить форму и её модуль списком операций и сравнить «до» и «после»
python3 $F edit Ext/form.frm --ops ops.json -o out.frm --bsl Ext/form.bsl --bsl-out out.bsl --render cmp.png

# нарисовать форму — в том числе в нескольких размерах окна
python3 $F render Ext/form.frm -o form.png
python3 $F render Ext/form.frm --sizes 715x440,968x561,min,max -o strip.png

# создать форму обработки по описанию
python3 $F new processing -o form.frm --root-xml МояОбработка.xml
# поля и таблицы привязываются к реквизитам и табличным частям обработки по её корневому XML
python3 $F generate описание.json --form form.frm --root-xml МояОбработка.xml -o form.frm --render cmp.png
```

Пример списка операций `ops.json`:

```json
[{"op": "set_form_title", "text": "Загрузка цен"},
 {"op": "add_element", "template": "TextBox", "name": "Поставщик", "box": [120, 40, 220, 19]},
 {"op": "add_button", "bar": "ОсновныеДействияФормы", "name": "Загрузить", "text": "Загрузить",
  "procedure": "Загрузить"},
 {"op": "append_procedure", "name": "Загрузить", "params": ["Кнопка"],
  "body": ["Сообщить(\"Загрузка цен\");"]}]
```

Для кнопки в модуле формы нужна процедура-обработчик: её добавляет операция `append_procedure`, а файлы модуля передаются ключами
`--bsl` и `--bsl-out`.

Навык придерживается правила: форму, которой уже пользуются, меняют только в пределах просьбы, а перекомпоновку всей формы делают
лишь по прямому указанию. Последняя строка отчёта `edit` показывает, сколько элементов затронуло изменение.

## Картинки

При отрисовке выводятся картинки, встроенные в саму форму (PNG, BMP, ICO, GIF), и общие картинки конфигурации — из её выгрузки
в файлы (ключ `--config` или каталог выгрузки, в котором лежит форма).

Картинки из библиотеки платформы — значки стандартных действий («Записать», «Печать», «Провести» и др.) и картинки, на которые форма
ссылается по коду или идентификатору, — берутся из каталога `form-ordinary/frm_codec/data/platform_pictures/`. В нём 299 картинок
в варианте для обычного приложения и файл `index.json` с их именами, кодами и размерами. Если файла картинки нет, на её месте рисуется
серый квадрат, а в замечаниях об этом говорится.

Картинки библиотеки взяты из платформы 1С:Предприятие 8.3.27; права на них принадлежат фирме «1С».

## Ограничения

- Карта формата и операции проверены на платформе 8.3.27 в режиме обычного приложения при разрешении экрана 96 DPI, а также
  на нескольких тысячах форм из действующих конфигураций. Формы с другим DPI читаются и изменяются, но расположение элементов
  и отрисовка для них не сверялись.
- Отрисовка приближённая: положение, размеры и картинки сверены со снимками экрана 1С:Предприятия, а то, чего на снимках не было,
  рисуется по описанию свойства и отмечается в замечаниях (`notes`).
- **Управляемые формы** (`Form.xml`) навык не поддерживает.
- Навык не подключается к информационной базе и не запускает платформу: загрузить изменённую форму в конфигурацию и проверить её
  в конфигураторе и в режиме 1С:Предприятие нужно самостоятельно.

## Как разрабатывался навык

**Сроки.** Чуть больше месяца: с 10 сентября по 26 октября 2026 года. За это время сделано 1 085 коммитов, выполнено около 365 задач
(по каждой — отчёт) и проведено 139 рецензий.

**Исполнители.** Навык полностью написан моделями Claude в среде [Claude Code](https://claude.com/claude-code) под руководством
человека. Роли распределялись так:

- **контролёр** (Claude Opus и Claude Fable) ставил задачи в письменных заданиях, принимал работу, вёл журнал и объединял ветки;
- **исполнители** (Claude Sonnet) писали код, тесты и документацию, каждый — в отдельной ветке git и отдельной рабочей копии;
- **рецензенты** (Claude Opus) проверяли сданную работу по первоисточникам — коду, снимкам экрана, данным набора форм, — а не по отчёту
  исполнителя;
- **тестировщики** (Claude Sonnet) проводили проверки в 1С: открывали формы в конфигураторе и в режиме 1С:Предприятие, делали снимки
  экрана и описывали увиденное;
- **человек** определял цели, принимал решения и оценивал результат.

**Проверка.** В навыке нет ничего придуманного: каждая запись карты формата и каждая операция подтверждены реальными формами
или опытом в 1С. Подтверждения брались из двух источников.

- **Набор форм.** Около 5 000 обычных форм из действующих конфигураций (зафиксированная копия, в публикацию не входит). На нём
  проверялись разбор, обратная сборка с побайтным совпадением, операции, типовые размеры и отступы.
- **Опыты и проверки в 1С по RDP.** Платформа 1С:Предприятие 8.3.27 на сервере Windows; модель подключалась к нему по RDP и сама
  работала с экраном.
  - В конфигураторе меняли одно свойство формы, сохраняли её и сравнивали файлы до и после изменения — так установлено назначение
    каждой позиции файла.
  - Формы, собранные навыком, загружали в тестовую базу, открывали в конфигураторе и в режиме 1С:Предприятие и делали снимки экрана.
    По ним с точностью до пикселя сверены расположение элементов и отрисовка: рамки, закладки, панели, картинки.

  Всего — около 230 сеансов работы, около 1 250 записей в журнале опытов и около 1 450 снимков экрана.

**Объём.** Около 90 тысяч строк кода на Python, около 140 тысяч строк тестов (226 модулей, около 3 900 тестов) и около 8 тысяч строк
документации.

## Состав

```
form-ordinary/
├── SKILL.md        вход для модели: команды, операции, указатель документации
├── FORMAT.md       карта формата form.frm
├── frm_json.py     точка входа: все команды
├── frm_codec/      перевод в JSON, изменение, создание, расположение элементов, отрисовка, досье
├── schema/         JSON-схема документа формы
└── docs/           документация по темам
```
