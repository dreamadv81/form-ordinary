# Разбор кода формы: редкие случаи

Справочник к `docs/brief-code.md`. Читайте только разделы, которые назвало задание `code-task.md` (в модуле есть соответствующий случай); основные правила, виды записей и пример — в инструкции.

## Выполнить

`Выполнить(Режим + "_Показать()")` вызывает процедуру по имени, собранному на лету. Граф связывает вызывающую процедуру с процедурами по образцу имени (`*_Показать`): литерал аргумента обёртки (`Перейти("Ожидание")`) — с одной, имя из переменной модуля (`ТекущийРежим + "_Скан()"`) — со всеми. Задание перечисляет такие вызовы.

- Литерал из открытия делает процедуру частью открытия: запись состояния в ней — как в `ПриОткрытии`.
- Процедура, до которой доходят только вызовы из обработчика действия, выполняется по действию: что она меняет, — `on_event` этого обработчика, по записи на переход (`condition` — когда переход идёт, `lines` — строки в процедуре режима); запись состояния в ней откажут. Переход на экран — эффект `current` с `affects` «Панель/Страница»: по нему строится картинка экрана.

```
1 Процедура ОбработкаОповещения(Событие, Данные, Источник)
2     Выполнить(ТекущийРежим + "_Скан(Данные)");
3 КонецПроцедуры
4 Процедура Сотрудник_Скан(Данные)
5     ЭлементыФормы.Экраны.ТекущаяСтраница = ЭлементыФормы.Экраны.Страницы.Сотрудник;
6 КонецПроцедуры
```

```json
{"kind": "on_event", "target": {"form": true}, "event": "ОбработкаОповещения", "condition": "режим ожидания, скан бейджа", "lines": [5, 5],
 "quote": "ЭлементыФормы.Экраны.ТекущаяСтраница = ЭлементыФормы.Экраны.Страницы.Сотрудник;", "effects": [{"what": "current", "affects": ["Экраны/Сотрудник"], "text": "экран сотрудника"}]}
```

## Таймер

Процедуру, которую код подключает как `ПодключитьОбработчикОжидания("Тик", 30)`, платформа вызывает через интервал уже после открытия; в файле формы такого события нет. Запишите её как `on_event` с целью `{"form": true}` и `event` «обработчик ожидания» (годится и имя процедуры): то, что она меняет на экране (текст кнопки, видимость, обновление списка), — в `effects`. Запись вида состояния (`visibility`, `enabled`, …) внутри обработчика ожидания отклоняется: при открытии она не выполняется, а перемена по таймеру — это `on_event`. Таймер, подключённый в процедуре действия, к открытию не относится.

## Кнопки, созданные кодом

- **Создание.** `Кнопки.Добавить(…)`, `Кнопки.Вставить(…)` — `created` с целью `{"button": [панель, кнопка]}`; имя создаваемой кнопки стоит в цитате. Созданное по условию (`condition` не пуст) и с вычисляемым именем на рисунке не рисуется, созданное безусловно рисуется.
- **Вычисляемое имя.** `Кнопки.Добавить("Печать" + Строка(Номер), …)`: `created` с `name_expr` — выражением имени (не короче трёх знаков, не литерал в кавычках; кнопку с известным именем записывают с этим именем), целью `{"button": [панель, ""]}` и той же панелью в цитате (`<Панель>.Кнопки…`).
- **Кнопка в меню.** Меню другой кнопки лежит по пути от панели: `Панель.Кнопки[0].Кнопки.Вставить(3, "Выбор")` при первой кнопке «Действия» — цель `{"button": ["Панель", "Действия", "Выбор"]}`; цитата показывает обращение к меню, на полосе панели такая кнопка не рисуется. Это только для кнопок, которые код создаёт в меню. Кнопка, которая есть в файле, — всегда `[панель, кнопка]`, а цитата обращается к ней так, как это делает код (`ЭлементыФормы.КП.Кнопки.Статус.Кнопки.Сбросить.Доступность` → цель `{"button": ["КП", "Сбросить"]}`).
- **`Кнопки.Очистить()`.** Цель одна: у панели `{"element": панель}`, у подменю `{"button": [панель, подменю]}`; `value` — «все кнопки»; подменю остаётся на панели, очищаются его кнопки. Вложенная панель или меню называются так, как в задании; командная панель внутри панели закладок — своим именем, `{"element": "КП"}`.
- **`Кнопки.Удалить(…)`** убирает одну кнопку: цель `{"button": [панель, имя кнопки]}`; имя неизвестно — `other` с причиной.
- **Процедура, привязанная кодом: `Новый Действие("Имя")`.** Процедура «Имя» — обработчик действия кнопки, которую создал код (в модуле формы или в общем модуле, которому передана форма). Задание ставит её в таблицу событий строкой «кнопка, созданная кодом»: `on_event` с `event` «действие кнопки, созданной кодом», целью `{"form": true}` (где бы ни лежала панель); `lines` — в процедуре «Имя».
- **Путь через подменю, созданное кодом.** Подменю заводит запись `created` с целью `{"button": [панель, "Печать"]}`; записи о его кнопках называют путь `{"button": [панель, "Печать", кнопка]}` и принимаются после неё, даже если кнопок подменю в файле нет.
- **Цикл по кнопкам меню.** `Для Каждого К Из ЭлементыФормы.КП.Кнопки.Вид.Кнопки Цикл К.Пометка = (К.Имя = "Вид_" + ТекущийВид)`: одна запись на кнопку меню (`checked`, цель — кнопка), цитата — строки цикла с обращением к меню, имя кнопки — в `condition`.

```json
{"kind": "created", "target": {"button": ["КнопкиПечати", ""]}, "name_expr": "\"Печать\" + Строка(Номер)", "value": "Печать", "condition": "для каждой печатной формы",
 "lines": [22, 22], "quote": "КнопкиПечати.Кнопки.Добавить(\"Печать\" + Строка(Номер), ТипКнопкиКоманднойПанели.Действие, \"Печать\");"}
{"kind": "enabled", "target": {"button": ["КП", "Сбросить"]}, "value": "Ложь", "condition": "статус «Выполнен»",
 "lines": [40, 40], "quote": "ЭлементыФормы.КП.Кнопки.Статус.Кнопки.Сбросить.Доступность = Ложь;"}
```

Первая запись — кнопка, которую код добавляет по условию: на рисунке её нет, в досье она названа с условием. Пример цикла по меню:

```json
{"kind": "checked", "target": {"button": ["КП", "Вид_Список"]}, "value": "Истина", "condition": "текущий вид «Список»", "lines": [50, 51],
 "quote": "ЭлементыФормы.КП.Кнопки.Вид.Кнопки Цикл\n    К.Пометка = (К.Имя = \"Вид_\" + ТекущийВид);"}
```

## Оформление строк

`ОформлениеСтроки.ЦветТекста = …` в обработчике `ПриВыводеСтроки` и `ОформленияСтрок` в обработчике `ПриПолученииДанных` относятся к таблице, чей это обработчик: `appearance` с целью-таблицей (или колонкой), имя таблицы в цитате не нужно — оно в параметре процедуры. `<Оформление>.Ячейки.<Колонка>.Текст`, `.ЦветФона`, `.ЦветТекста`, `.Шрифт` — тоже `appearance` таблицы или колонки, `value` словами. Текст ячейки не заголовок колонки: `title` с `.Ячейки.` в цитате навык отклоняет.

```
30 Процедура ТоварыПриПолученииДанных(Элемент, ОформленияСтрок)
31     Для Каждого Оформление Из ОформленияСтрок Цикл
32         Оформление.Ячейки.Количество.Текст = Формат(Оформление.ДанныеСтроки.Количество, "ЧДЦ=0") + " шт";
33         Если Оформление.ДанныеСтроки.Выполнено Тогда Оформление.ЦветФона = WebЦвета.СветлоЗеленый; КонецЕсли;
34     КонецЦикла;
35 КонецПроцедуры
```

```json
{"kind": "appearance", "target": {"column": ["Товары", "Количество"]}, "value": "текст ячейки — количество с «шт»", "lines": [32, 32],
 "quote": "Оформление.Ячейки.Количество.Текст"}
{"kind": "appearance", "target": {"element": "Товары"}, "value": "выполненные строки — светло-зелёный фон", "condition": "строка выполнена",
 "lines": [33, 33], "quote": "Оформление.ЦветФона = WebЦвета.СветлоЗеленый;"}
```

## Псевдоним элемента

Переменная держит элемент, а действие стоит в другой строке или процедуре.

- **В той же процедуре:** цитата из нескольких подряд идущих строк — где получен псевдоним и где с ним что-то делают (`Панель = ЭлементыФормы.Связь;` и следующая строка).
- **Из другой процедуры** (`мКнопка = ЭлементыФормы.Комментарий;` в одной, `мКнопка.Видимость = Ложь;` в другой): имени цели в цитате нет. Добавьте `alias` — `{"lines": [от, до], "quote": точная цитата строки присваивания}`; навык проверит обе цитаты и то, что `quote` обращается к этой переменной.
- **Имя выражением или цикл** (`Элемент = ЭлементыФормы[Имя]`, цикл по `ЭлементыФормы` и `Колонки`): назовите цель, только если она одна и однозначно следует из кода (цикл — одна запись на то, что он делает, с отбором в `condition`); иначе `other` с целью `{"form": true}` и причиной.

```json
{"kind": "visibility", "target": {"element": "Комментарий"}, "value": "Ложь", "condition": "", "lines": [60, 60], "quote": "мКнопка.Видимость = Ложь;",
 "alias": {"lines": [12, 12], "quote": "мКнопка = ЭлементыФормы.Комментарий;"}}
```

## Свойства формы и имена вне формы

- `ЭтаФорма.Панель` — панель самой формы, цель `{"form": true}`; `ЭтаФорма.<свойство>` (`Заголовок`, `ТолькоПросмотр`, `Панель`, `Ширина`…) — свойство формы, `missing` не бывает. `ЭтаФорма.Панель.ЦветФона = …` — `appearance` с целью форма.
- Имя, которому присваивают значение и которого нет среди элементов, реквизитов формы и объекта, — локальная переменная (`ЗаголовокОкна = "Настройка";`): на экране ничего, записи нет.
- Имя в обращении к элементу, а элемента с таким именем нет (код пишет `ЭлементыФормы.Токен_Старый`, а элемент называется «Токен», и «Токен_Старый» — его данные или устаревшее имя): `missing` с целью `{"name": "Токен_Старый"}`, цитата содержит обращение.
- Устаревшее имя после правки формы (`УстаревшаяНадпись`): `missing`, в досье «код обращается к «УстаревшаяНадпись», такого элемента нет».

```json
{"kind": "appearance", "target": {"form": true}, "value": "фон формы светло-кремовый", "lines": [70, 70], "quote": "ЭтаФорма.Панель.ЦветФона = Новый Цвет(252, 250, 235);"}
{"kind": "missing", "target": {"name": "УстаревшаяНадпись"}, "condition": "", "lines": [31, 31], "quote": "ЭлементыФормы.УстаревшаяНадпись.Видимость = Ложь;"}
```
