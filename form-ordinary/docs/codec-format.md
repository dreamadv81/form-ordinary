# Кодек: формат, JSON и карта

Часть навыка `form-ordinary`; навигатор и таблица «Тема → файл» — в `SKILL.md`. Документ описывает, как читать и записывать JSON формы, смысловой дифф, какие пропавшие поля замечает проверка, особые значения и карту позиций.

**Корпус** — набор настоящих форм из конфигураций, по которому проверялась карта формата.

## JSON без стандартного разборщика

JSON формы нельзя пропускать через стандартный разборщик (`json` в Python, `jq`). Дробное число хранится в нём так, как записано в файле формы, например `1e2`. Стандартный разборщик прочитает его как число с плавающей точкой и запишет `100.0`: значение то же, но запись другая, и в собранной форме появятся отличия, которых никто не вносил. Программно читайте и записывайте этот JSON функциями `frm_codec.json0.loads` и `frm_codec.json0.dumps`. Править файл вручную в текстовом редакторе безопасно.

## Смысловой дифф

Команда `diff --meaning` сравнивает формы по именам полей карты, а не по позициям. Платформа при каждой выгрузке выдаёт кнопкам командной панели новые идентификаторы и переставляет записи действий, поэтому позиционный дифф (`frm_json.py diff` без `--meaning`) двух выгрузок одной формы показывает десятки «изменений». Смысловой дифф заменяет идентификатор кнопки устойчивым именем «панель/набор/имя кнопки», выстраивает записи действий в порядке этих имён и сравнивает деревья JSON.

Списки, у членов которых есть устойчивый ключ, сравниваются по ключу: добавленная кнопка не сдвигает остальные, а лишний член списка выводится целиком. Отдельную строку `…/порядок` дифф выводит, только если изменился взаимный порядок общих членов списка. У кнопок набора это порядок на экране, поэтому перестановка двух кнопок даёт одну такую строку, а добавление или удаление кнопки — ни одной. Позиционный дифф печатает адреса позиций, смысловой — пути по ключам JSON.

## Какие пропавшие поля замечает проверка

Карта не знает, сколько детей (значений) должно быть у блока, поэтому проверка замечает пропажу поля только в одном случае: когда поле удалено из середины блока и остальные значения сдвинулись бы на одну позицию влево. Тогда сборка отказывает и называет адрес. Если удалено последнее поле вида `u…`, отказа нет: файл соберётся с блоком на одно значение короче. Команда `validate` предупреждает на уровне 2, если такая длина блока на этой позиции в корпусе не встречалась. Предупреждения строятся по сводке `frm_codec/data/corpus_stat.json`; для позиции, которой в сводке нет, предупреждения не будет. **Длина, которую платформа записывает сама.** Корпус не видел всего, что пишет платформа: диаграмма Ганта, список выбора без представлений, панель с несколькими страницами в панелях нового строения дают длины блоков, которых в корпусе нет, хотя запись совпадает с записью платформы. Для таких длин предупреждение называет это словами («но такую длину платформа записывает сама … запись навыка совпадает с записью платформы, длина редкая для корпуса; на работу формы не влияет»). Источник — `frm_codec/data/platform_lens.json`: длины блоков, которые встретились в формах, сохранённых конфигуратором, и которых нет в корпусе, и строение списка страниц панели (сколько страниц и какой длины записи платформа писала). Список страниц панели стоит на разных позициях тела панели (перед ним разное число списков стиля), поэтому его узнают по строению, а не по адресу. Длина, которой нет ни в корпусе, ни у платформы, остаётся предупреждением прежнего текста, и её сверяют с исходным файлом. Конец блока окончательно проверяют сравнением с исходным файлом: `frm_json.py diff`. **Сводкой, когда их много.** У формы старой конфигурации, которую корпус видел мало, таких предупреждений бывают десятки на форму, а форма при этом собирается байт в байт. Если их больше трёх, `encode`, `validate` и `edit` печатают одну строку: число позиций по видам элементов (у `edit` поштучно идут новые, сводкой — те, что были и в исходной форме). Перечень целиком — ключ `--all-warnings`.

## Особые значения

| Значение | Как записывается | Правила |
|---|---|---|
| Целое число, запись которого не сохраняется при переводе в число (например, `00010101000000` с ведущим нулём) | обёртка `{"num": "<текст как в файле>"}` | Именованное поле карты вида INT такое значение не принимает: позиция называется `u<индекс>`. Обёртка с текстом, который без потерь записывается числом (`{"num": "7"}`), вызывает отказ. |
| Пустое значение между запятыми, `{0,,60}` (встречается в узлах диаграмм и графической схемы) | `null` на уровне 0 | `null` — не пустая строка и не отсутствие поля. Пустое значение допустимо в середине блока и в начале (`{,1}`), но не в конце: `{1,}` вызывает отказ. Именованное поле карты значение `null` не принимает: такая позиция называется `u<индекс>`. В выводе `diff` пустое значение печатается как `{"empty": ""}`, потому что там `null` означает «адреса не было». |
| Блок `#base64:` | обёртка `{"base64": "…"}` | Платформа пишет base64 строками по 64 знака и ставит `CR CR LF` после каждой полной строки. Если разбивка на строки другая, разбор запоминает её во втором поле обёртки: `"layout": "flat"` (одна строка без разрывов) или `"layout": "no-tail"` (разделитель только между строками, перед `}` его нет). У обычной разбивки поля `layout` нет; значение `"norm"` вызывает отказ, как и любое значение `layout`, которое даёт те же байты, что обычная разбивка. Любая другая разбивка вызывает отказ разбора с адресом. |

## Карта позиций

`FORMAT.md` описывает все позиции формы: у каждого поля указаны имя, вид и примечание. У каждого поля карты есть вид источника знания — документация, проверка в предприятии или формы конфигураций; поле без источника карта не принимает. Файлы `FORMAT.md` и `schema/frm.schema.json` создаются из карты командой `frm_json.py schema` и вручную не правятся. Команда работает только в репозитории навыка; в установленной копии эти файлы лежат готовыми.

## Чего кодек не делает

* Карта описывает все типы элементов, встреченные в корпусе; элемент незнакомого типа уровень 1 не раскрывает и переносит полем `raw` без изменений (`FORMAT.md`, раздел «Типы вне карты»). Полей и перечислений, найденных в корпусе, но не внесённых в карту, нет.
* Часть имён карты корпус на их позициях не подтверждает: там лежит значение другого вида или строения. Тогда кодек имя не использует, значение сохраняет, а позицию называет `u<индекс>`.
* Поля записи страницы самой формы платформой не проверялись; события встроенного контейнера страниц проверены в предприятии. Какие случаи добавления и удаления страниц формы проверены и где нужен `unverified`, описано в `docs/form-pages.md`.
